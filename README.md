# 在庫管理Webアプリ ― 入出庫履歴・発注提案

Python / FastAPI と MySQL系データベースを使った、個人制作の在庫管理Webアプリです。
ブラウザーで在庫を確認し、入庫・出庫を記録できます。出庫履歴から平均消費量を求め、在庫が何日分あるかと発注数量の目安を表示します。

> **学習・ポートフォリオ用の開発途中の作品です。** 新規DB用SQLとAPIの列定義をそろえ、MariaDB 10.4.28で入出庫・履歴・発注提案などのAPI統合テストを実施しています。実店舗での運用やブラウザーを通した全操作の確認は行っていません。

## 主な機能

| 機能 | 実装内容 |
| --- | --- |
| ログイン | ユーザーIDとパスワードで認証し、JWTを発行 |
| 在庫一覧 | 商品名・カテゴリ・現在庫を表示。商品選択で入出庫フォームに反映 |
| 入出庫登録 | 数量・理由・メモを指定。在庫更新とともに、変更前後の数量と操作ユーザーを記録 |
| 入力チェック | 0以下の数量、不正な入出庫種別、在庫不足の出庫を拒否 |
| 履歴検索 | 最新100件を取得し、画面側で入出庫種別・ユーザー・商品名の部分一致で絞り込み |
| 発注提案 | 集計期間・納品までの日数・安全在庫日数・出庫理由を指定して計算 |
| 管理者機能 | ユーザー一覧・追加、パスワード再設定API。スタッフからの管理API利用を拒否 |

商品・カテゴリを新しく登録する画面や、自動発注機能はありません。

## 使い方の流れ

1. ユーザーIDとパスワードでログインする。
2. 在庫一覧から商品を選ぶ。
3. 入庫または出庫、数量、理由・メモを入力して登録する。
4. 在庫一覧と履歴で変更結果を確認する。
5. 発注提案で、平均出庫量・残り日数・推奨発注数を確認する。

## 発注提案の仕組み

画面とAPI名には「AI分析」という表現が残っていますが、**現在は機械学習・生成AI APIを使わず、平均出庫量に基づくルールで計算しています。** 将来のAI活用に向けた基盤として制作しています。

```text
1日あたりの平均出庫量 = 対象期間の出庫合計 ÷ 対象日数
在庫の残り日数 = 現在庫 ÷ 1日あたりの平均出庫量
確保したい日数 = 納品までの日数 + 安全在庫日数
目標在庫 = 切り上げ(1日あたりの平均出庫量 × 確保したい日数)
推奨発注数 = max(0, 目標在庫 − 現在庫)
```

例えば、14日間で28個出庫、現在庫10個、納品まで7日、安全在庫3日なら、平均出庫は2個/日、残り5日分、目標在庫20個、推奨発注数10個です。出庫履歴がない場合、残り日数は推定しません。

季節性や需要の変化を予測するものではなく、発注判断の参考値です。

## ローカル起動の準備

以下はコードに基づく手順です。依存ライブラリのバージョンは固定されておらず、環境による互換性の確認が必要です。公開サーバーへのデプロイ手順ではありません。

### 1. Python環境

Python 3.10以上と、ローカルのMySQL / MariaDBを用意します。PowerShellでリポジトリのルートから実行します。

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install fastapi uvicorn pymysql "pydantic[email]" "passlib[bcrypt]" PyJWT
```

### 2. データベース

検証用の新しい `inventory_db` を作成し、phpMyAdminなどで `Portfolio_2026/inventory_db.sql` をインポートします。既存の業務用DBには適用しないでください。

新規DBには不足していた `reason_code`、`before_quantity`、`after_quantity` も作成されます。初期データの過去の履歴は、当時の値が不明なためこれらの列を `NULL` としています。

**旧版SQLで作成済みのMariaDBの場合：** データをバックアップしたうえで、対象DBを選択して [移行SQL](Portfolio_2026/migrations/001_transaction_details.sql) を実行します。既存テーブルやデータを削除せず、不足列だけを追加します。MariaDB 10.4.28では繰り返し適用してもデータが保持されることを検証しています。MySQLでの同じ構文の互換性は未確認です。

`main.py` の `get_conn()` を自分のローカルDB接続設定に合わせます。現在のコードは `localhost` / ユーザー `root` / 空パスワードを前提にしています。

### 3. ログイン用アカウント

付属SQLには管理者ユーザーがありますが、対応する平文パスワードは文書化されていません。検証用DBの管理者に、自分で決めたパスワードのハッシュを設定する必要があります。

```powershell
.\.venv\Scripts\python.exe -c "from getpass import getpass; from passlib.context import CryptContext; print(CryptContext(schemes=['bcrypt']).hash(getpass('Local demo password: ')))"
```

出力したハッシュを、検証用DBの管理者（初期データでは `user_id = 1`）の `password_hash` に設定してください。実際のパスワードやハッシュをリポジトリへ追加しないでください。

### 4. 起動

静的ファイルの参照先が相対パスのため、`Portfolio_2026` ディレクトリで起動します。

```powershell
cd Portfolio_2026
..\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

- アプリ画面：<http://127.0.0.1:8000/app/>
- API仕様・操作画面：<http://127.0.0.1:8000/docs>
